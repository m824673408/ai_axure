## 交互

- **查询条件编辑**：新增媒体（MediaSelector）、事件类型（下拉）、状态（下拉）三项可选项，与既有设备标识输入框、事件时间范围选择器共同组成查询区。
- **查询结果**：点击后应用当前条件，页面仅展示同时满足全部已填写条件的记录，摘要条数同步更新。
- **条件填写与生效分离**：输入/选择只更新草稿条件，未点击「查询结果」前不影响列表。
- **重置条件**：新增按钮，点击后清空全部条件（含已应用条件）并恢复完整列表。
- **空态**：无匹配记录时展示「没有符合当前条件的归因结果」，摘要显示 0 条。
- **导出结果**：沿用既有静态按钮，本次无行为变化。

## 产品规则

- 多个条件按 **AND** 关系组合，记录需同时满足全部已填写条件。
- 未填写的条件不参与筛选（留空即不过滤）。
- 设备标识：
  - 使用**不区分大小写的包含匹配**；
  - 匹配对象为**完整设备标识**，非脱敏展示值；
  - 表格中仍展示**脱敏值**，不因筛选改变展示口径。
- 时间范围：按**自然日**计算，**包含开始日与结束日**（整日闭区间）。
- 重置后清空全部条件并恢复完整结果列表。
- 页面仅调整归因结果页，不修改导航、路由、全局 Layout、共享组件与主题。
- 使用静态演示数据，不接入真实查询接口。

## 风险

- **筛选值为前端常量，未与数据源联动**：事件类型（应用激活 / 首次付费）与状态（active / pending / archived）选项在页面内硬编码，若后续演示数据或真实接口枚举变化，会出现「选项选了但筛不出」的不一致。
- **媒体筛选依赖编码映射**：媒体筛选比较的是 `mediaCode`（ocean / tencent / kuaishou），表格展示的是媒体名称（巨量引擎 / 腾讯广告 / 磁力引擎）。MediaSelector 的取值口径若与数据源的 `mediaCode` 不一致，媒体条件将静默失效，且不会有报错提示。
- **时间比较的时区与解析方式**：行时间经 `new Date(row.time.replace(' ', 'T'))` 解析为本地时间后与 dayjs 的 `startOf('day')` / `endOf('day')` 比较，二者时区假设需保持一致；若演示数据或后续接口返回带时区的时间字符串，首尾日边界可能偏移。
- **状态类型约束**：`ResultStatus` 为 `'active' | 'archived' | 'pending'`，需与 `StatusTag` 支持的状态集合保持一致，否则可能出现标签渲染兜底或空值。
- **摘要条数为前端计算结果**：使用静态数据本地过滤，条数不代表真实查询总量；在无分页/无服务端查询的前提下，接入真实接口后「当前结果 N 条」的口径需重新定义（当前页 vs 全部）。
- **空态依赖 DataTable 契约**：空态文案通过 `locale.emptyText` 传入，属共享组件既有能力的使用，若共享组件后续调整该契约，页面空态会退化。
- **重置语义覆盖范围**：重置会同时清空草稿与已应用条件，隐含「重置即放弃未提交的编辑」，需确认与用户预期一致。
- **筛选行为无持久化**：条件不写入 URL 或状态存储，刷新后恢复完整列表，可能影响用户回访与结果分享场景。
